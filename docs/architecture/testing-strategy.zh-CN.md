# Micro 测试准则与分层

更新：2026-10-04。状态：测试准则，部分隔离用例已落地；具体运行结果随执行产物保存。

采用 AIY 的风险驱动、L0–L6 分层及证据边界，按 Micro 的 WPF、文件配置和 Codex 控制链重新落地。测试继续维护在本仓现有 `tests/`，不另建 private 测试仓，不迁移已有测试。分层描述验证责任，不要求建立七个项目、七套执行器或新的 CI。

[功能、测试与维护总纲](micro-maintenance-outline.zh-CN.md)负责功能导航；本文负责共用准则；[可更换按钮测试设计](keycap-test-design.zh-CN.md)负责具体场景。真实用户配置、聊天内容和运行证据不作为公开测试夹具。

## 1. 先定义用户结果，再选验证层

从用户旅程识别损失，选择能够证明该结果的最低层。纯规则由单元测试深入覆盖；文件保存、控件绑定、协议接线和真实进程各用对应层证明。每层保留真实的被测行为链，只替换明确的外部边界。不能用复制的生产算法生成预期，也不能用总是返回成功的替身证明动作有效。

五个维度分别维护：

| 维度 | 回答的问题 | Micro 示例 |
| --- | --- | --- |
| 功能分支 | 用户在做什么 | MC-03 更换绑定、MC-06 保存恢复 |
| 测试层次 | 证据能证明哪一段 | L1 控件事件，L3 实际文件重载 |
| 风险优先级 | 哪种损失先防止 | P0 配错目标、保存后丢绑定 |
| 执行时机 | 何时必须核对 | 修复期间、合并前、发行时 |
| 实现与执行状态 | 已实现什么，实际跑过什么 | 功能 Partial；某场景 NotRun |

P0 保护日常主线、已保存配置、目标身份以及发送／审批等外部结果；P1 保护重要分支、取消和恢复；P2 用于损失有限的低频组合。中文主线、键盘唯一入口、低频但不可恢复的误操作不能因属于“变体”而降级。优先级不由测试层次、代码行数或用例数量决定。

## 2. L0–L6 的责任与证据边界

| 层次 | 在 Micro 中验证什么 | 保留真实对象／可替换边界 | 能给出的证据与限制 |
| --- | --- | --- | --- |
| L0 场景化单元 | 目录与尺寸、绑定优先级、参数构造、目标代次、队列／反馈状态机、解析规则 | 使用生产规则；时间、ID、外部状态用最小输入或 fake | 证明规则、不变量和错误语义；不证明控件已接入、磁盘持久化或 IPC 接线。 |
| L1 组件与交互 | 真实编辑器、实际免驱 profile、控件选择、绑定事件、异步返回、禁用原因、可访问属性 | 真实 WPF 组件、绑定和 Dispatcher；替换进程、配置边界或时间时逐项注明 | 离屏可证明组件行为；不证明真实桌面焦点、物理键盘输入、像素布局或 UIA 识别。 |
| L2 协议与外部适配 | Codex 消息、动作参数、回执与状态读回、错误码、畸形响应、超时与断开 | 真实序列化／传输适配器，接合成接收端；只有实际经过本机管道／回环连接才计对应传输证据 | 证明协议与适配合同；直接回调替身不证明字节传输与序列化，合成原生控件树不证明实际 Codex 版本兼容。 |
| L3 存储与服务 | TOML／图标配置、真实写入重载、冲突、回滚、损坏恢复和清理 | 使用独立临时文件与真实读写服务；在明确写入点注入故障 | 证明文件格式与保存语义；重建服务对象不等于进程重启，两文件失败恢复不自动证明崩溃原子性。 |
| L4 进程与系统边界 | 主窗口到控制组件的接线、目标发现、系统激活／URI 边界、连接生命周期、取消与释放 | 实际宿主适配器和引用包；OS／Codex 替身及真实子进程分别记录 | 证明所经过的系统边界合同；同进程模拟端不证明跨进程启动／崩溃／恢复，参数检查不证明系统已激活目标。 |
| L5 端到端旅程 | 从实际 Micro 进程的编辑入口，更换→保存→关闭重开→执行→用户可见结果 | 真实 Micro 可执行程序与入口；隔离 Codex 接收端或真实 Codex 必须标明 | 少量旅程证明整条接线。隔离 E2E 只证明到合成接收端；真实 Codex 全链另需实际结果。离屏组合场景不标 E2E。 |
| L6 专项证据 | 高风险逻辑变异抽样、性能、资源释放、权限／数据边界、稳定性、原生平台和发行验收 | 按风险选择工具、数据、实际环境与本次产物 | 性能要测量，真实 DPI／输入法要实机，发行要本次包。专项不是再重复全部业务矩阵，也不等于必须全部人工执行。 |

架构与静态检查是配套检查面：依赖方向、API／资源合同、编译及静态分析不能替代 L0–L6 的运行证据。现有 `WindowDesignTests` 等文件可能同时包含组件断言和静态合同，按用例实际责任标注，不能凭文件名判层。

Micro 没有 Electron 的 main／preload／renderer 层；L4 对应自身宿主、Windows 及外部进程边界。不机械移植 AIY 的框架、SQLite、命令名或覆盖率数字。

## 3. 场景卡与用例归属

每项设计最少记录以下字段，详细用例中的 A／E／S／J／G 编号继续使用；需要多层证据时引用同一个场景，不复制多份需求。

| 字段 | 内容 |
| --- | --- |
| 身份与依据 | 场景 ID、MC 功能分支、需求／缺陷、负责的生产模块 |
| 风险 | P0／P1／P2、要保护的不变量、发生错误时用户失去什么 |
| Given／When／Then | 准确前提、动作或事件顺序、可观察结果与禁止副作用 |
| 判据 | 独立预期；读取哪个持久值、目标身份、控件状态或接收端结果 |
| 层次与替身 | 主责层、补充层、保留的真实链、替换的边界、不能推出的结论 |
| 设计方法 | 等价类、边界值、决策表、状态转换、不变量或组合覆盖 |
| 故障与时序 | 注入位置、受控事件、超时／取消、固定缺陷种子与数据 |
| 执行计划与证据 | 运行时机、版本、实际范围、结果、首跑／重试、证据位置 |

例如 J03 的用户结果是“发送移到其他位置后，仍只对正确目标发送一次”。P0 不变量是不能因物理位置或旧目标误发。L1 证明当前按钮经真实绑定产生正确意图；L4 证明后台激活、前台第二次操作以及目标代次校验的宿主接线；L2 证明发送参数与结果确认；L5 只取一个代表位置证明真实进程全链。后台、目标切换和隐藏布局分别有零发送断言，不在 L5 重跑所有位置组合。

## 4. 组合、时序与缺陷种子

先把已知缺陷的准确条件、事件顺序及独立判据固定为永久回归，再扩展组合。不能等待组合生成器偶然选中 S01 紧凑格式、S05 半保存、G01 目标 A→B→A 等事故条件。

| 方法 | 适用内容 |
| --- | --- |
| 等价类 | 合法／未知动作、已确认会话／草稿／未知目标、展开／紧凑配置 |
| 边界值 | 推理强度上下限、单宽／双宽、计时截止前／到期／之后 |
| 决策表 | 图案默认动作、用户已存绑定、手选动作及支持状态的优先级 |
| 状态转换 | 排队→取消→断开→重连；保存→冲突→恢复；目标 A→B→A |
| 性质／不变量 | 不串写其他槽位、稳定身份、取消前零副作用、重复输入不重复外部操作 |
| Pairwise／t-way | 有效位置、布局、图案类别、动作族、语言等独立配置因素 |

普通组合采用最低合适层的有效 pairwise。风险明确的组合采用三因素或定向更高阶，例如“发送绑定位置 × 前后台 × 目标代次变化”。合并槽位与拆分槽位不可能同时显示，先写约束再生成组合；“用户请求了不支持动作”是有意义的拒绝用例，不当作无效组合删去。保留因素、取值、约束和生成种子，才能复查覆盖了哪些有效组合。

15 个命令和八个位置分别要求覆盖，但不强制生成 120 条完整旅程。若确有独立的生产路由表，可在低层穷举其有限组合；每个位置仍需真实入口证据，每类执行机制仍需相应边界证据。不能为了凑矩阵另造只在测试中使用的路由模型。

配置组合不覆盖事件顺序。并发测试用受控任务、时钟或信号分阶段释放：先断言等待期间没有提前保存／派发，再释放结果，最后断言准确内容、身份和状态。不能先等竞态消失才触发操作。

## 5. 夹具、定位与等待

- 用合成配置、技能、会话和响应；每例独立临时目录及接收端身份。共享只读样本，不共享可变配置。时间、ID、文件路径、进程和外部通信依赖沿现有边界最小注入，不增加测试专用生产旁路。
- 单元与隔离测试不落到默认用户配置、真实 Codex 或真实服务；不修改全局 HOME。结束时取消任务、释放句柄，校验临时路径归属后清理。
- WPF 优先按控件语义、可访问名称和稳定槽位／动作 ID 定位，不依赖翻译后的文本位置、数组下标或私有字段。用稳定 ID 定位后仍核对可访问名称与状态。
- 操作只触发一次，等待有界的只读结果。禁止在轮询中反复点击、保存、发送或审批；不吞异常，不用增加超时掩盖竞态。
- 新增或修改的异步用例不以固定 `Sleep`／`Task.Delay` 作为“准备好了”的判据。计时合同推进受控时钟；真实调度检查单列容差及目的。旧有等待在涉及相应用例时维护，不为本设计全仓改写。

## 6. 执行时机与当前能力

现有入口为 [`scripts/test.ps1`](../../scripts/test.ps1)：运行 `tests/CodexMicro.Desktop.Tests` 的 Release 测试并写 TRX。它没有七个独立层次车道，也不能仅因其中类名含 Acceptance 就宣称已有 L5 或 L6。当前 `BehaviorAcceptanceRig` 的部分 IPC 是合成接收端，原生 UI 也是替身；其结果必须按实际边界解释。

| 时机 | 要做的检查 | 结论边界 |
| --- | --- | --- |
| 纯设计／文档改动 | 文本、链接、编号、分层一致性与差异 | 文档检查不产生功能运行结论。 |
| 实现或修复期间 | 先固定缺陷种子，再运行受影响的现有单元／组件／集成；按改动执行编译和静态检查 | 记录选择范围，不把局部通过扩成全量通过。 |
| 合并前 | 适用的现有自动化回归、编译和静态检查；核对必需边界是否仍缺证据 | 不因 P2、覆盖率高或重试通过而跳过既定必要检查；不存在的套件记为缺口。 |
| 发行前 | 固定源码、测试和依赖输入；适用自动化、代表旅程及实际产物验证 | 生产 E2E 绑定本次包／可执行产物和摘要；构建成功、安装升级、商店认证分别记录。 |

独立发行的 Micro 可执行程序全入口 L5、系统鼠标命中和安装验收仍待覆盖。真实 Codex 的启动同步／新会话 Fast 应用级自动化见第 9 节；它使用生产 WPF 窗口的测试宿主，不替代发行包启动验收。后续执行遵循该任务的明确授权与环境条件；一次真实旅程覆盖多个责任时，不重复计成多个已完成场景。

同仓记录源码／测试提交及未提交差异、依赖版本、Windows／Codex 版本、构建参数、执行时间与测试范围。工作区有其他任务改动时保留它们，移动中的本地快照只作诊断；固定发布证据不得借用旧提交或另一个控制组件源码仓的结果。不要为取得“干净”状态擅自提交、暂存或重置。

## 7. 专项与结果维护

变异测试仅抽样目标保护、绑定优先级、保存恢复等高风险逻辑，检查断言能否检出错误；不设全仓每次执行门禁。性能按同一配置规模、会话／技能数量和事件速率比较冷／热耗时、调用数、读写量和内存；没有实测基线不设空泛阈值。资源专项观察反复开关编辑器、取消与重连后的任务、计时器和句柄是否释放。

覆盖率只用来找遗漏，不继承 AIY 历史百分比，也不靠重复路径增数。首跑失败后重试成功单列不稳定性，不能抹去第一次失败。隔离不稳定用例须有问题、责任和到期条件，不能静默移除 P0 及必要发行验证。

功能状态、测试实现状态、运行结果分别登记。运行结果至少区分 `Pass`、`Fail`、`NotRun`，跳过原因与首跑／重试另列。每条结果回链到场景和具体版本；截图、日志或成功回调只在能支持所声称的结果时作为证据。缺少实机、进程重启或包验证时准确保留待验范围。

## 8. 当前隔离测试入口

[`scripts/test-keycaps.ps1`](../../scripts/test-keycaps.ps1) 默认运行现有测试项目的全部用例并采集覆盖率；加 `-Focused` 只运行标记 `Scope=Keycaps` 的专项用例。它不启动真实 Micro／Codex 窗口，不修复生产文件，不自动跳过失败。依赖测试 SDK 已有的 Microsoft Code Coverage 收集器；测试项目单独引用 Tomlyn 校验 TOML 语义，生产项目不引入该依赖。

[`tests/keycaps-obligations.json`](../../tests/keycaps-obligations.json)列出本轮隔离验收义务的预期场景数，以及尚未覆盖的边界。运行输出分别记录执行完整性和断言通过情况：一个失败用例可以证明缺陷已被检出，但不能算功能通过。清单只覆盖其明确列出的范围，不作为全软件覆盖分母；变更能力或支持范围时同时审查清单与独立预期。

输出写入忽略的 `.artifacts/keycap-tests/`：TRX、Cobertura、日志、执行前后输入摘要和 `summary.json`。源码、测试或脚本在执行中变化会使结果降为诊断；缺失报告、义务未执行或测试失败返回非零退出码。覆盖率列出整个已加载 Core／Windows 模块和七个具名按键文件，不删除难测分支，不自动将覆盖率设为发行通过条件。

新增代码使用合成数据与临时目录。目录创建、清理及少量已有同步配置 API 仅在隔离测试中调用，数据为数 KB；它们不提供 UI 响应性能证据。原生适配测试运行实际引用包的控制器，但 Windows 观察／操作边界是合成对象；协议回调替身、实际命名管道和真实系统分别标注。

## 9. Codex 应用级启动与 Fast 回归

入口：[`scripts/test-micro-live.ps1`](../../scripts/test-micro-live.ps1) 的 `-StartupFast`；用例为 [`StartupFastVerification.cs`](../../tests/CodexMicro.LiveSmoke/StartupFastVerification.cs)。运行前打开一个可明确识别的已有 Codex 会话，并保留 Fast 按键绑定。测试会暂时将 Codex 置前、打开空白输入页和模型菜单；运行期间不要在该窗口输入或导航。

```powershell
./scripts/test-micro-live.ps1 -StartupFast
# 可指定独立报告，保留修复前后的首跑结果
./scripts/test-micro-live.ps1 -StartupFast -ReportPath .artifacts/micro-e2e/comparison.json
```

| 场景 | 独立判据 |
| --- | --- |
| 启动同步 | 从宿主 Main 入口记录窗口构造、首帧和连接／会话同步；启动同步回归预算为 5 秒。裸 `app://-/index.html` 不得被当成已确认离开会话而抑制侧栏回退。 |
| 新会话 Fast 往返 | 点击实际绑定的 WPF 按键，每次获得一次回执；原生 CheckBox 的速度标签和 Micro Fast 图标同时达到预期。 |
| 连续两次 Fast | 两次点击分别获得回执，原生速度和图标恢复初始状态；不在轮询中重复点击。 |
| 目标保护与恢复 | 已有会话的模型、推理强度、服务档位不变；关闭测试宿主后读回草稿原始速度，并导航回原会话确认。 |

该测试保留生产窗口、软件传输、共享控制包、真实 Codex 进程和系统 UIA；Micro 输入是 WPF 路由点击，不覆盖操作系统指针命中、托盘／单实例入口或商店安装包冷启动。测试不提交消息、审批或修改 Micro 持久设置；清理失败返回非零并写入报告。首次观察原生速度与清理会打开菜单，普通轮询只读，有界等待。

默认报告在忽略的 `.artifacts/micro-e2e/startup-fast.json`，记录各阶段耗时、断言、恢复结果、Windows 和控制包版本。机器上的原始报告与修复前后比较不进入公开文档；一次通过仅证明该版本、该数据集和本次调用链，不是通用启动性能承诺。
