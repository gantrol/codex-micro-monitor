# 可更换按钮测试用例重设计

更新：2026-10-04。

状态：测试设计已部分落地，当前实现覆盖隔离规则、编辑器、文件和适配边界；主窗口系统接线、完整进程旅程与实机仍有缺口。范围为 Windows 免驱 Micro 的键帽编辑、动作绑定、保存、执行和反馈，以及相关的现有测试；配额、窗口缩放等独立功能不因本次设计重写。

从[功能、测试与维护总纲](micro-maintenance-outline.zh-CN.md)按功能分支规划；本文维护其中按键专项的具体用例与验收合同。共用的风险、L0–L6 分层、组合方法和执行规则维护在[测试准则与分层](testing-strategy.zh-CN.md)，测试沿用本仓现有项目。

行为依据：[可更换按键与 Sketch](keycap-actions.zh-CN.md)及当前源码。当前依赖为 `CodexControl` / `CodexControl.Windows` `0.1.0-local.4`，已加入已确认草稿上的 Fast／Plan 路径。后续实施前再次核对依赖版本和源码，不把旧检查记录当作当前测试结果。

## 1. 测试要回答的问题

一次更换成功，必须同时满足：用户选定的动作得到保存；重新加载后动作、图标和提示一致；在正确目标上按一次只执行对应动作一次；缺少条件时明确说明原因；取消、失败或目标变化不会触发其他动作。

分别报告四种能力，禁止将它们合并成“按钮通过”：

| 能力 | 通过证据 |
| --- | --- |
| 图标可选／可显示 | 目录、尺寸和离屏实际绑定正确；不是只检查属性有值。 |
| 绑定可保存／可恢复 | 保存后用全新对象读取，值与选择一致，其他位置和非 Micro 配置保留。 |
| 动作可执行 | 独立模拟接收端观察正确动作、正确参数、正确目标和调用次数；需要效果确认的路径还必须观察状态变化。 |
| 真实应用可用 | 对特定 Codex 版本实际验证并记录前后状态；隔离测试不能提供此结论。 |

当前目录基线为 40 个键帽、15 个受支持命令：10 个键帽的默认动作有路径，25 个默认动作未接入，5 个未分配。未实现动作的“拒绝测试通过”只证明防误执行有效，功能仍标记 `NotImplemented`；不能计入功能正常数量。

## 3. 分层与夹具

### 3.1 用例的主责层与补充证据

以下是设计归属，不是当前已具备或已通过的套件清单。一个场景可以需要多层证据，各层只承担自己的验证责任；不用每层重跑整个矩阵。

| 层次 | 按键专项主责 | 场景关联 | 不能据此宣称 |
| --- | --- | --- | --- |
| L0 场景化单元 | 默认／已存／手选动作优先级，目标与草稿身份，队列和反馈状态转换，目录与参数规则 | E01–E05 的决策表；G01–G08 的状态机；A01–A16 参数与拒绝条件 | 静态辅助函数通过不证明窗口走了这条规则；解析成功不证明文件已保存。 |
| L1 WPF 组件 | 真实免驱编辑器的选择、取消、禁用和异步绑定；主界面位置、布局与输入事件 | E01–E11；G07–G09；J01–J05 的入口段 | 离屏事件不证明实际键盘、桌面焦点或 Codex 原生控件可用。 |
| L2 协议与适配 | 实际命令参数、响应解析、状态读回、超时、断开；合成接收端记录结果 | A01–A16 中适用的协议／适配合同；G03–G06 | 所有命令不必都走同一种协议；URI 请求成功不证明已导航，原生 UI 替身不证明真实 UIA。 |
| L3 文件存储与服务 | 真实临时配置写入、合法格式、重载、冲突、部分保存与恢复 | S01–S10；J01–J05 的保存段 | 对象重建不等于进程重启；普通回滚不证明崩溃原子性。 |
| L4 进程与系统边界 | 主窗口实际路由到控制组件；激活／发送顺序、身份代次、取消清理与系统调用合同 | A08–A09 的窗口专用路径；J03；G01–G06 | 直调 Transport 绕过窗口不能证明宿主接线；同进程模拟不能证明跨进程生命周期。 |
| L5 端到端旅程 | 真实 Micro 进程中更换、保存、关闭重开、执行和可见结果 | 首选 J01、J03、J05 的代表路径；J04 在技能链变更时补充 | 现有 J 设计默认是 L1＋L3＋L2／L4 组合；实际进程未运行前不能标 L5。使用合成 Codex 时仍非真实 Codex 全链。 |
| L6 专项 | 真实系统输入／DPI／原生识别、包兼容；高风险断言变异抽样、资源与响应性能 | MC-08／MC-09；G04 清理；目标保护与 S05 的风险抽样 | 离屏渲染不证明布局；绿色自动化不证明性能、真实版本兼容或安装升级。 |

现有文件按用例归类：`SettingsWindowDesignTests` 的行为部分、`PanelAcceptanceTests`、`SoftwarePresentationTests` 主要归 L1；真实临时文件的 `CodexMicroConfigWriterTests`／`MicroProfileSettingsTests` 归 L3；`BehaviorAcceptanceTests` 与 `SoftwareControlRegressionTests` 按实际经过的 L2／L4 边界记录。`WindowDesignTests` 的静态合同、纯规则和组件行为分别标注，不整文件冒充某一层。

### 3.2 数据与保存夹具（L3）

使用测试专属临时目录，分别放置合成的 Codex TOML、Micro 图标配置和技能文件。读写真实文件以验证实际格式与重载，不读取或修改用户的 `.codex/config.toml`。每例结束验证临时路径归属并清理；不改变进程级 HOME 或 Codex 配置路径。

保存合法性采用显式预期字段／独立标准 TOML 解析结果。现有环境没有合适解析器时，先用固定合法文本结果检查，明确其边界；是否增加仅用于测试的解析依赖另作最小实现选择，不复制生产宽松解析器充当判据。

### 3.3 离屏组件夹具（L1）

沿用 `WpfUiCollection` 和 STA Dispatcher。创建真实编辑器／键盘组件，传入临时配置与真实免驱 `softwareProfile`，通过控件选择和绑定命令／事件进入生产流程，不调用 `Show`、`ShowDialog`，不模拟真实鼠标或键盘，不启动浏览器、UIA 或真实 Codex。

当前保存事件直接设置 `DialogResult`，不能让离屏测试为此打开模态窗口。实施时将保存结果与“请求关闭编辑器”做最小分离，让实际按钮仍调用同一保存逻辑；测试断言保存结果与关闭请求。不以反射设置 `IsAvailable` 或 `_followKeycapDefault` 等私有字段制造通过条件。

当前主窗口布局观察器默认指向用户配置，前台判断也直接依赖静态系统调用。新增窗口入口测试前，提供最小的临时布局／前台观察注入点，复用已有的激活与选择读取委托。涉及草稿、模型服务时同样替换操作系统和外部进程边界，不能让默认构造偷偷落到本机服务。不为此引入新的 DI 框架或通用测试平台。

### 3.4 协议与宿主边界夹具（L2／L4）

沿用真实 `SoftwareMicroTransport`、包内控制组件和 `BehaviorAcceptanceRig`。只替换外部 IPC、App Server、原生界面观察／操作、URI 打开以及时钟／故障时机。模拟接收端按预先配置的场景变化，独立记录副作用；产品的动作选择、目标保护、成功判定均保留真实实现。

每例至少检查：结果分类、动作名称与参数、目标身份、变更次数、不应出现的其他变更。RPC 回成功但状态不变、UI 已变而回执丢失必须能独立模拟。设置有界超时，超时应报错，不能静默跳过。

只有真实穿过序列化与管道的部分计协议传输证据；直接调用的 App Server 回调和 `SyntheticUiDesktop` 明确记为替身。接线测试必须经过生产窗口入口；启动／退出／重启／崩溃跨进程合同另需真实受控进程，不能用同进程对象重建替代。

### 3.5 真实进程旅程与专项（L5／L6）

单列真实 Micro 进程的隔离 E2E、真实 Codex 全链、Windows 平台矩阵和本次发行产物验证。各项可自动化或人工，但需记录实际环境和替身边界；本次仅设计，不执行。提交消息、批准、分叉、停止任务等使用专用目标和预先说明的副作用，不操作已有工作聊天。缺少真实验证时标记 `NotRun`，不能借用隔离测试结果。

产品代码可用的最小依赖注入继续服务实际职责，不增加测试专用命令或隐藏绕过。L5 实施前先核对测试数据隔离、现有驱动与执行授权；不为名义上补齐层次新增框架。

## 4. 覆盖矩阵

### 4.1 位置与键帽

可保存位置共八个：ACT06、ACT07、ACT08、ACT09、ACT10、ACT11、ACT10_ACT11、ACT12。合并与拆分布局互斥，不能把八个位置当作同屏按钮。

- 40 个键帽分别检查默认动作、尺寸、唯一标识和实际图标绑定。基线数据由测试显式列出并与官方导出目录及 Micro 扩展核对，不能把 `SoftwareRoute` 的返回值同时用作输入和期望。
- 单宽／双宽选择分别覆盖，另外给每个位置一个代表性更换保存用例，验证位置不串写。
- 15 个命令逐一验证结果合同，八个位置逐一验证实际入口和保存不串位。动作族、位置和布局在 L1／L2／L4 做有约束的组合覆盖；不强制生成 120 条完整集成旅程。若生产路由存在独立有限映射，低层可穷举 15 × 8，并明确它只证明映射。
- 技能作为独立动作族纳入位置覆盖，另覆盖更换图标后名称与路径不变。推理强度经过真实窗口专用路径；发送固定覆盖 ACT06、ACT10、ACT10_ACT11、ACT12 的入口差异，不能全部直调 Transport。
- 错误状态按动作族、存储格式和故障边界选取；不展开“40 图标 × 15 动作 × 8 位置 × 所有故障”的重复组合。

组合因素包括位置、合并／拆分布局、图案类别、动作族、已有绑定类型和语言。先排除单／双宽、隐藏槽位等不可能组合，普通因素采用有效 pairwise；发送绑定位置 × 前后台 × 目标代次采用定向三因素覆盖。每个命令的核心效果与拒绝条件、E01／S01／S05 等缺陷种子始终保留，不能被抽样替代。

### 4.2 目标状态

| 状态 | 判据 | 核心期望 |
| --- | --- | --- |
| T1 已确认会话 | 会话 ID、目标版本一致 | 执行当前会话的动作，读回／回执符合对应动作合同。 |
| T2 已确认草稿 | 前台首页输入框、模型选择器身份及版本一致 | Fast、Plan、推理强度、Sketch、发送可按各自前置条件执行；不能假装存在已有会话 ID。 |
| T3 目标未知 | 缺少选择证据、身份冲突，或仅有空 ThreadId | 不把未知当草稿；依赖目标的动作零派发，给出不可用原因。 |
| T4 导航中 | 正在 A→B，尚未确认 B | 不执行 A 的滞后动作，也不提前修改 B；确认完成后才恢复。 |
| T5 Codex 后台 | 其他应用占据前台 | 发送第一次仅激活。依赖前台的其余动作不得操作其他窗口；推理键的改进合同见第 7 节。 |
| T6 身份在等待中改变 | A→B、A→B→A，或草稿 D1→D2、选择器替换 | 即使最终 ThreadId／空值相同，旧版本意图不能重新生效。 |

### 4.3 每个命令的结果标准

| ID | 命令 | 成功证据 | 必测拒绝／不确定情况 |
| --- | --- | --- | --- |
| A01 | `newTask` | 正确的新会话 URI 恰好一次；导航确认层观察新草稿后才更新当前目标 | URI 打开失败、导航未确认；链接派发成功不冒充页面已打开。 |
| A02 | `forkThread` | 创建返回新 ID，打开该 ID；源会话不变 | 创建失败零打开；已创建但打开失败明确部分完成，不能重试创建分叉。 |
| A03 | `composer.toggleFastMode` | 已有会话的 tier 往返且保留 model／effort；草稿菜单的 Fast 状态读回 | 模型不支持、只有请求回执、草稿身份变化；六次快速输入仍按顺序切换。 |
| A04 | `composer.togglePlanMode` | 已有会话 Plan/default 往返；草稿计划状态往返，输入文本／附件／其他设置保留 | 缺少计划入口、旧模式未知、输入文本变化、身份丢失或不能读回；不发送临时 `/p`。 |
| A05 | `toggleReviewTab` | 当前范围只验收正确会话的 Review 打开请求／导航确认 | 往返切换单列功能缺口，不能用“打开两次”代替切换通过，见第 7 节。 |
| A06 | `approval.approve` | 唯一待审批请求，正确 request ID、accept 决定及确认回执 | 零个／多个、审批过期、类型不支持、无确认；零错误审批。 |
| A07 | `approval.decline` | 同 A06，决定为 decline | 与 A06 成对验证，防止共用代码写反决定。 |
| A08 | `composer.increaseReasoningEffort` | 在模型允许列表中上调一档；已有会话与确认草稿分别观察结果 | 上限无变化也不报成功变更、模型不明、后台、导航中、草稿身份丢失。 |
| A09 | `composer.decreaseReasoningEffort` | 在模型允许列表中下调一档 | 下限、同 A08 的目标条件；保留 model／Fast／Plan。 |
| A10 | `turn.cancel` | 对选中会话当前 turn 发送一次停止并获得有效回执 | 无活跃 turn、turn 在读取后替换、目标切换；不停止新 turn。 |
| A11 | `composer.submit` | 已在前台时一次有效操作发送；后台首按仅激活，之后另一次有效操作才发送；输入框／运行状态变化支持结果 | 后台第一次、激活失败、空输入且无可发送附件、菜单遮挡、目标切换、确认超时；禁止重发。 |
| A12 | `composer.sketch` | 观察到添加菜单中唯一绘图项，打开一次并确认草图编辑器 | 菜单项缺失／多义／禁用、其他菜单打开、目标变化；编辑器已开时不再调用。 |
| A13 | `toggleSidebar` | 侧栏状态发生相反变化 | 控件不可用、后台、只回成功而状态未变化。 |
| A14 | `navigateBack` | 后退一次且目标／页面身份变化 | 无历史、禁用、导航未确认；不循环调用。 |
| A15 | `navigateForward` | 前进一次且目标／页面身份变化 | 同 A14，方向必须准确。 |
| A16 | 技能绑定 | 插入指定名称及路径的技能 mention，原草稿其余内容保留 | 路径失效／相对路径、同名异路径、文本粘贴而非 mention、剪贴板被外部更改、目标变化；不得发送消息。 |

Sketch、草稿 Fast／Plan 的原生观察数据分别覆盖英文、简体中文、繁体中文和不匹配名称；这里的语言场景验证识别行为，不验证某个控件名字字符串恰好出现在源码。

## 5. 编辑、保存与执行用例

### 5.1 编辑与拆分

| ID | 场景 | 预期 |

| E01 | 默认未配置 MIC1／EMPT1 → 选择 NEW、SKETCH、FAST（分别参数化） | 带入对应受支持默认动作，可保存；重新打开仍是该动作。 |

| E03 | 用户手动选择动作后再连续换图标 | 后续图标选择不覆盖手选动作。 |

| E05 | 默认不支持图标 → 配受支持动作；受支持图标 → 配不支持动作 | 前者可保存执行；后者不可保存和执行，且原因可读。 |

| E08 | 取消、Esc、关闭编辑器 | 两份持久配置和实际动作均不变；异步加载晚到不复活窗口或触发保存。 |
| E09 | 拆分→分别配置 ACT10、ACT11→合并→再拆分 | 两个单键及合并键三份配置保留，显示和入口位置正确。 |
| E10 | 鼠标对应事件、Space、Enter 操作已换绑按钮 | 每次有效操作一个意图；按下／松开不重复派发，拆分键不继承语音的长按语义。 |
| E11 | 未支持／未分配按钮禁用 | 不派发，不伪装成功或亮失败红灯；用户仍可从设置入口重新编辑该位置。 |

E01–E05 必须传入免驱 `softwareProfile`。至少一个场景从真实控件选择开始，不能全部直接创建最终绑定对象。

### 5.2 保存与重载

| ID | 前置状态／故障注入 | 预期 |
| --- | --- | --- |
| S01 | 展开 TOML／槽位 inline table／整个布局 inline table | 保存结果为合法配置，重新加载值唯一且正确；无重复表或旧 inline 值回盖。 |
| S02 | CRLF／LF、注释、Unicode、带引号路径、非 Micro 设置 | 往返不改变非目标槽位及无关配置的含义，不损坏字符串或换行。 |
| S03 | 全新配置／缺少 Micro 表 | 仅创建必要数据；默认布局和其他文件不受影响。 |
| S04 | TOML 写入或替换失败 | 动作、图标、内存状态均保持旧值；错误可见，可重试。 |
| S05 | 动作写入后图标写入失败 | 按第 7 节保存合同恢复一致状态，不能只提示失败却启用新动作。 |
| S06 | 写入期间外部编辑配置 | 在受控时点制造外部变更；拒绝覆盖，保留外部版本和用户尚未保存的选择。 |
| S07 | 两个编辑器保存不同位置／同一位置，或与拆分开关同时保存 | 不丢失其他位置；同一位置冲突明确报告，不用过期全文件覆盖。 |
| S08 | 文件损坏／未知动作／未知键帽 | 不崩溃、不意外恢复为可发送动作；给出可恢复状态，拒绝无依据覆盖原文件。 |
| S09 | 重置布局后重新创建所有读取对象 | 动作和图标一起恢复默认，外部配置保留；失败不显示成功。 |
| S10 | 关闭并重新创建配置服务与主界面 | 图标、动作、布局、提示均来自已保存数据；不靠旧内存对象通过。 |

失败注入使用临时目录内的受控文件锁／可控写入边界，以及信号栅栏控制发生时点；避免依赖管理员权限、机器磁盘容量或睡眠碰运气。

## 6. 目标、并发与反馈

| ID | 场景 | 预期 |
| --- | --- | --- |
| G01 | 等待模型目录、IPC 或原生菜单时 A→B、A→B→A | 旧输入失效，目标变更后不再发出旧动作；晚到结果不能更新当前按钮状态。 |
| G02 | ThreadId 均为空，但 D1→D2 或选择器被替换 | 通过草稿身份和版本区分；不能因为两个 null 相等而继续。 |
| G03 | Fast 六次快速点击：已有会话／草稿 | 依次执行六次、结果交替；模型和推理强度不变，末态准确。 |
| G04 | Fast 队列中切换目标、断开、关闭窗口 | 旧队列取消或拒绝，不重连后重放到新目标；任务与资源可结束。 |
| G05 | 正在执行时再按发送、审批、分叉或停止 | 不进入自动重试队列；被拒绝的额外输入不会迟到执行。 |
| G06 | 发送前取消／已操作后超时或取消 | 前者零变更；后者按证据给结果未知或已确认，不错误承诺“未执行”；均不重发。 |
| G07 | 新操作替换旧活动状态，随后旧定时器到期 | 旧计时器不清除新状态；确认成功、暂不可用、结果未知、失败有不同分类。 |
| G08 | 绿灯、黄灯、红灯计时恢复 | 按当前约定 650 ms／5 s 恢复空闲，保留事件详情；断开连接后不恢复为已连接状态。 |
| G09 | 切换语言／换绑动作／重载配置 | 名称、禁用原因和无障碍状态一起更新；不残留旧键帽的功能名。 |

用可推进的时间源或小范围可替换延迟验证 G07–G08；避免每例真实等待五秒。可以保留一项带容差的调度集成检查，不能用极窄墙钟阈值制造不稳定失败。

G01–G06 逐个登记事件顺序，例如“捕获 A 的代次→阻塞结果→切到 B→切回 A→释放旧结果”，分别在释放前后断言零误派发及零旧状态覆盖。组合覆盖不能替代这些顺序。等待只轮询只读状态，不重新触发操作；不通过预先等待 UI／队列稳定消除待测竞态。

## 7. 尚需用目标行为约束的问题

以下是本设计提出的验收目标，尚不是实现完成声明。它们与“维持现有正常行为”的回归用例分开记录。

| 问题 | 拟采用的验收合同 | 当前边界 |
| --- | --- | --- |
| 后台 MIND+/MIND- 无声退出 | 前台不满足时禁用并显示原因；在鼠标按下后才失去前台时返回未执行反馈，零变更。恢复前台及目标证据后重新可用。 | 不默认增加自动激活或后台修改能力；若产品改为首按激活，需先修改此合同。 |
| 两份文件只保存一半 | 普通“保存失败”意味着恢复原动作和图标，且窗口保持可编辑。无法回滚时必须明确报告部分保存，重新读取实际状态，并避免展示旧状态却执行新动作。 | 两文件进程崩溃恢复另列后续持久化要求；本轮先覆盖可捕获的保存／回滚失败，不承诺跨文件原子性。 |
| 紧凑配置 | 对已经承诺可读取的格式，保存后仍合法且生效。修复前将相关成功往返场景标记为失败／缺口。 | 不允许通过删除紧凑格式用例或仅用宽松解析器通过来隐藏问题。 |
| DIFF 往返 | 当前“打开 Review”可有单独验收；“再按关闭”保留为未实现功能项。 | 本设计不自行扩大功能范围或改掉动作含义；只有实现往返后才能将其升级为 toggle 验收通过。 |
| 活动灯译文调整 | 按现行文案合同维护资源断言，行为测试独立验证状态及语言更新。 | 不凭一次字符串差异判定按钮不能执行，也不把旧测试改绿当成功能修复。 |

## 8. 实施次序与完成标准

### 8.1 按用户损失排期

| 优先级 | 本轮场景 | 选择理由 |
| --- | --- | --- |
| P0 | E01–E05、E08–E11；S01、S04–S08、S10；J01–J05；G01–G06；A01 及发送／审批／停止等动作的身份和副作用保护 | 主线可更换、已存选择不丢、不串位置或目标、不重复产生外部操作。边界场景不因频率低而降级。 |
| P1 | 其余受支持命令的完整成功与恢复合同；E06–E07；S02–S03、S09；G07–G09 | 支持范围的重要分支、读写兼容、状态与恢复。S02 若造成损坏、G09 若误导实际动作等按损失升 P0。 |
| P2 | 已保证核心可达后的非阻断外观、低频合法组合和额外性能探索 | 不降低原生输入、语言主线或可访问性核心操作的优先级；测得阻塞后重新定级。 |

上述是场景内风险分支的排期；例如 G03 的连击队列保护是 P0，A03 的普通模式往返可按 P1 维护。实际场景卡写一个明确优先级及理由，不能仅按整个测试文件继承。

### 8.2 实施与运行顺序

1. 核对当前版本，记录现有基线；建立独立场景数据和临时配置注入，确认测试不会连接本机 Codex。保留仍有效的既有回归。
2. 按 P0 场景先固定历史缺陷的条件与事件顺序，在能证明结果的最低层复现，再补实际入口接线；不把“当前会失败”改写成期望成功。
3. 完成每个受支持命令的合同、每个位置的入口证据和受约束组合；补草稿 Fast／Plan、Sketch、审批、分叉和停止的效果／失败证据。
4. 合并重复样式检查，移除被新用例替代且没有生产调用的旧 HID 辅助函数测试；不为减少失败删除有效场景。
5. 完成反馈和语言用例，按实现变更运行相关现有单元、组件、隔离集成及构建／静态检查。合并与发行的必要检查按测试准则单列；缺少 L5／L6 实施或运行条件时保持缺口和 `NotRun`。

每个场景沿用准则中的场景卡：ID、MC 分支、风险／不变量、Given／When／Then、独立判据、主责与补充层、替身边界、设计方法、故障时序、责任模块和执行时机。执行时再附位置、动作、布局、目标身份、版本、实际副作用、首跑／重试及证据。功能状态 `Implemented`、`Partial`、`NotImplemented`、`Unassigned`、测试实现状态与执行结果 `Pass`、`Fail`、`NotRun` 分列。

完成本轮重设计的标准是：每个已声明支持的动作都有明确成功证据和拒绝条件；八个位置都经过实际绑定路径；保存失败与目标变化有可控复现；存在完整编辑到执行场景；测试结论能准确说明哪些只验证隔离行为、哪些已经实际确认。

测试继续使用现有 .NET 项目；基础入口为 [`scripts/test.ps1`](../../scripts/test.ps1)，专项计量入口为 [`scripts/test-keycaps.ps1`](../../scripts/test-keycaps.ps1)。后续获准的测试重建只修改测试和夹具，生产代码保持原状；检出的产品失败保留为失败，不修改断言使其通过。
