# Windows 任务键灯光状态

更新：2026-10-10。本文描述任务键，不是三个连接／操作指示灯。

## 中心点输入状态（2026-10-10）

中心点现在独立于外围任务灯光：默认紫色，观察到已保存的有效输入时为绿色；单纯选中不再替换为白色或薄荷色中心点。外围运行、等待、错误、未读与选中效果继续使用下述投影。两页任务键共享按任务 ID 读取的输入状态，额外图标和角标不进入界面。

输入来源为现有全局状态中的持久化 composer 草稿，不从任务运行流、rollout 或历史消息推断。支持范围、轮询/保存延迟、未保存的纯附件限制及验证边界见[草稿标记说明](draft-indicator.zh-CN.md)。

## 全链路排查矩阵（2026-10-08）

排查边界是 Windows 独立 Micro：任务身份 → owner 发现／订阅 → 完整快照／补丁 → 当前回合与运行状态 → rollout／问题／未读 → 单调快照 → 两页键帽。以下按输入、生命周期和交付故障分类，不把某两个复现当作全部问题。

现有灯态测试主要使用合成 runtime 快照，仍有覆盖缺口。Codex 26.1002.7124.0 的 `threadRuntimeStatus`、`resumeState` 和 turn 的 `status` 分别更新，不能把前者永久当作唯一依据。尤其 `turn/started`、`turn/completed` 会更新回合并广播快照，不保证同一条消息同步更新 runtime。历史回合只有在会话已经恢复且包含最新端时，才可作为当前回合依据。

| 类别 | 必须区分的情形 | 排查结论／处理 |
| --- | --- | --- |
| 启动 | 从未运行；运行中重启 Micro；已完成后重启 Micro | 首次可信快照统一重建，不持久化猜测的灯态 |
| 启动 | Codex 尚未启动；owner 尚未发现；首次快照超时 | 状态未知，后续重试；不能据此判定 idle 或失败 |
| 加载 | `needs_resume` 的旧 `inProgress`；`resuming`；`resumed` 的当前回合 | 已修改：原实现忽略加载状态；现在按加载状态限定回合证据 |
| 生命周期 | runtime 先变／turn 先变；正常完成；中断；失败；失败后新回合 | 已修改：仅 runtime 会冻结旧 idle／active；现在统一读取当前回合 |
| 历史 | legacy turns；canonical history；历史分页；旧回合完成晚到 | 只采用最新端和正确 turn ID，不按对象枚举顺序选当前回合 |
| 提交 | 请求准备中；未确认提交；提交失败；连续开始下一轮 | 活跃提交不能被上一轮完成状态覆盖 |
| 等待 | 审批；同步问题；异步问题；多个问题；回答；Skip | 审批／问题仅附着于运行中的同一回合；保留 Skip 的既有证据边界 |
| 多源 | runtime 与 rollout 不同回合；旧错误；旧问题 | 已修改：原投影无回合关联；已知当前回合时禁止跨回合附加错误和问题 |
| 连接 | Micro 管道断开；Codex owner 退出；IPC reset 但管道仍在 | 失效旧订阅，等待完整快照；连接丢失不是任务失败 |
| owner | owner 更换但进程未退出；重新索取 following 状态 | 已修改：处理 following-status-requested，重新发现 owner 并建立快照基线 |
| 连接竞态 | discovery 在 reset／断线前发出、之后返回 | 已修改：用连接代次拒绝旧发现结果 |
| 交付 | 重复快照；旧快照；重复补丁；修订缺口；先补丁后快照 | 旧消息不回滚；缺口重建快照，重复补丁不应撤销有效状态 |
| 协议 | 错误 owner／host；未知版本；坏补丁；错误数据形状 | 不采信或撤销依据，允许后续重新同步 |
| 无事件 | 长时间运行／等待，没有内容增量；最后一条更新未送达 | 已修改：30 秒无有效流消息后重新发现 owner 并请求完整快照；超时撤销观察，不判任务结束 |
| 查询 | roster／未读查询失败；单个任务不可用 | 已修改：保留身份并继续读取已有 rollout；订阅恢复由独立定时入口推进 |
| 文件 | 缺失／锁定／权限失败；半行；坏行；截断；路径更换 | 已修改：临时读取失败保留问题，仍处理 IPC 已接受的回答；配置读取失败沿用缓存，不撤销订阅。半行、坏行和截断沿用原解析机制 |
| 文件 | 同一路径替换，长度更短／相同／更长 | 已修改：Windows 按实际读取句柄的卷序列号和 128 位文件 ID 校验身份；文件更换后清空游标、半行、回合和问题状态，从头重建 |
| 名单 | 增删；排序；容量上限；同一任务移出再移入 | 按 thread ID 管理，离开名单撤销订阅，重新进入重新取快照 |
| 呈现 | 两页；选中／未选中；悬停冻结位置；动画；回调乱序 | 保留任务身份；状态快照按 revision 应用，选中效果不改变任务状态 |
| 窗口 | 隐藏／恢复；关闭；监控器释放 | 隐藏撤销观察，恢复后取新状态；旧回调不能恢复旧灯 |
| 未读 | 完成已读／未读；手工标未读；运行时仍带旧未读 | 未读独立于执行状态，不能把所有完成都强制显示绿色 |

验证层次必须分开记录：现有自动化覆盖、静态协议核对、实际进程／界面验收互不替代。本轮不新增或改写测试，不操作真实 UI；新增判定分支若没有现成自动化用例，必须保留为验证缺口。

目前缺少专门自动化覆盖的分支：`resumed` 的 runtime／turn 分歧、canonical 最新端和分页、未确认提交、跨回合错误／问题、following 状态重新索取、连接代次竞态、静默校准、文件读取失败时接受回答，以及同路径替换日志。它们已逐项静态核查并落实到实现，不能把原有用例通过当作这些分支已被动态验证。既有自动化的 IPC 和 WPF 场景属于隔离链路，不代表真实 Codex 与安装版 Micro 的重启验收。

只有 `task_started`、没有 `task_complete` 或 `turn_aborted` 的 rollout，可能来自已经停止的任务。它证明日志中有未闭合回合，不能证明 Codex 仍在运行；不能依据日志年龄设置一个超时来猜测任务是否停止。

## 状态依据

`SoftwareThreadObserver` 复用问答回复的桌面 IPC 订阅，观察当前 roster 的所有任务，最多 16 个。订阅采用 4 路并发，每个 owner 发现及首快照等待限制为 2 秒；单个会话不可用不阻断其他会话。窗口隐藏、关闭或任务移出 roster 时撤销对应观察。

| 证据 | 投影 |
| --- | --- |
| owner 会话 `resumed`，最新端回合 `inProgress`，或存在未终结的提交 | 运行中，蓝色；即使 runtime 的更新尚未到达 |
| owner 会话 `resumed`，最新端回合 `completed`／`interrupted`／`failed` | 空闲／空闲／错误；即使 runtime 仍暂留 `active` |
| `needs_resume` 或没有可用的最新端回合，仅实时 `active` | 运行中，蓝色；未恢复的历史 `inProgress` 不参与 |
| `resuming` 且没有实时 `active` | 未知，不能根据加载前的 idle 判定任务已结束 |
| `waitingOnApproval` 或命令／文件审批请求 | 等待输入，橙色 |
| `waitingOnUserInput`、用户输入请求，或当前运行回合的日志有待回答问题 | 待回答，黄色；审批和问题只附加到尚在运行的回合 |
| 没有当前回合证据，实时 `idle`，日志只有未闭合回合 | 空闲，撤销蓝色和旧问题状态 |
| 实时 `systemError` 或当前回合失败 | 错误；不能用另一回合的旧错误码描述当前失败 |
| 没有可信实时状态，只有未闭合日志 | 未知，撤销蓝色；选中效果仍可为白色 |
| Micro 监听连接／owner 丢失，或 owner 发现返回 `no-client-found` | 实时依据失效；保留任务身份，等待重新订阅，不据此报错 |
| 无实时状态但日志有结束事件 | 保留明确的空闲／错误结果 |

未读仍来自原有未读观察，不从结束事件推断。运行、审批和错误状态优先于未读；空闲或未知任务可以显示绿色未读状态。只有缺少当前回合证据时才沿用日志中的明确错误；新回合的成功结束不能重新显示上一回合的容量不足错误。

`CodexThreadActivityStream` 只保留 runtime、加载状态、请求方法、提交是否终结、回合 ID／状态／错误码，以及 canonical history 的排序和最新端边界，不保存消息或工具输出。canonical history 使用最后一个 `newerBoundary.status=exhausted` 的尾部 island，按 `entries[].value` 查找实体，不能用 `entitiesByKey` 的枚举顺序或刚加载的旧页面决定当前回合。完整快照和两种路径形式的补丁共用同一投影。

订阅只接受对应 owner 的版本 11 会话流。修订缺口、不支持的版本、无效补丁都会撤销运行依据，并等待重新发现和完整快照。单次超时不据此判定任务已中断。历史快照不能覆盖较新的补丁，重复／晚到补丁不再被当作修订缺口；单调观察序号防止延迟回调恢复旧蓝灯。订阅回调在锁外交付；状态到 WPF 的呈现切回 Dispatcher。

每次有效流消息刷新观察时间；30 秒无消息时，已有 2 秒定时入口触发 owner 发现和 `following=true`，利用 owner 对重复 following 返回完整快照的行为校准状态。同一修订的快照只确认连接仍能交付，不回放旧状态；新修订正常应用。该周期是观察校准周期，不是任务超时，不会把长时间思考改成完成或失败。最多 16 个任务、4 路并发、每项 2 秒等待；因此故障恢复时间还包含调度、排队和连接等待，不能保证固定 30 秒内完成。新增加的完整快照传输成本尚未做同数据集前后测量，不宣称性能提升。

`ipc-connection-reset` 也会撤销所有旧订阅的实时状态。该通知不要求管道物理断开；下一次订阅刷新按原任务 ID 重新发现 owner 并订阅完整快照，owner ID 未变化时也会重建修订基线。重置后、重新订阅前到达的旧流消息不再恢复灯态；重置前发出的 discovery 响应也不能建立新订阅。`thread-stream-following-status-requested` 同样触发对应任务的 owner 重新发现，不能仅依赖客户端退出通知。

Micro 重启或重建监听连接不代表 Codex 任务失败。IPC `Disconnected` 表示当前客户端的管道关闭，不能区分监听端关闭、连接故障与任务执行端退出；`no-client-found` 只表示当次 owner 发现没有处理端，不能证明未闭合回合发生了错误。两者均不生成 `turn_interrupted` 或持久化错误标记。失效观察仍保留已经确认过的回合身份，避免上一回合的终态在断连后冒充本回合结果。重新订阅得到可信快照后按同一规则重建状态。临时 roster 查询失败保留身份并继续读取其 rollout，未读查询失败也不阻止任务订阅启动。

`CodexTaskMonitorService` 对全量轮询、问题轮询和实时观察使用相同投影。原始 rollout reader 继续保留未闭合回合这一事实，不在解析器中把它伪装为已结束。

rollout 的终态现在保留 turn ID；明确属于另一回合的结束／错误事件不能关闭当前回合，同一回合结束后的重复 start 不重新点亮。无 turn ID 的旧格式记录缺少关联证据，仍按文件顺序处理，这一限制不能通过超时补足。文件读取沿用既有后台同步增量解析器：`ReadAsync`／`ReadPendingQuestionsAsync` 的 `Task.Run` 内执行，最多 16 个任务；每次读取新增字节，首次读取仍扫描全文件。首次大日志扫描及锁等待的耗时尚未测量。

Windows 的 `CodexRolloutFileIdentity` 在同一个已打开的句柄上读取 [FILE_ID_INFO](https://learn.microsoft.com/en-us/windows/win32/api/winbase/ns-winbase-file_id_info)，用卷序列号加文件 ID 比较文件身份。该系统接口仅有同步形式，每次读取 24 字节元数据，在上述后台解析流程中执行，不另开文件、不为身份判断重扫内容。文件身份改变或长度缩短会重置解析器；身份查询失败按读取失败处理，保留上一观测并继续接受 IPC 回答，下一轮重试。读取期间路径被替换时，当前句柄继续指向旧文件，下一轮打开新文件时识别变化。平台调用保留在 Windows 项目，通过身份读取函数传给 Core；未提供函数的解析器只处理追加与可见截断。身份校验不把同一文件对象内部的任意历史改写当成受支持的追加日志。

## Skip 问题状态

异步问题的 Skip 不写入回答记录。`CodexQuestionSkipObserver` 按当前会话、问题标题和按钮身份观察跳过；保留 Invoke 通知，并复用现有鼠标钩子记录同一 Skip 按钮内的按下和松开。后台下一次成功观察到该按钮消失或切换到另一个问题时，才确认这次点击。这样卡片卸载导致 Invoke 通知丢失时，仍能清除对应问题。

鼠标钩子只读取缓存的屏幕坐标和原生窗口句柄，不执行 UIA、文件读写或吞掉 Skip 点击。按钮祖先查找使用 Raw View，避免漏过不在 Control View 中的卡片容器。没有点击证据的卡片消失、自动收起和 Escape 不算跳过；窗口或会话变化时放弃待确认点击，Invoke 和鼠标观察重复到达只处理一次。同一会话仍有其他待答问题时保留黄色，跳过本身不结束回合。

跳过状态仅在当前监控器生命周期内有效；Codex 本身未持久化这一状态，Micro 重启后不能从 rollout 还原它。此路径尚无真实界面点击验收，现有自动化仅覆盖解析后的跳过、多问题保留及状态投影。

## 回归场景与边界

- [组件场景](../../tests/CodexMicro.Desktop.Tests/TaskLightingComponentTests.cs)：刚开始／长时间未闭合的日志、监控器重建、元数据不可用时保留任务身份、显式停止／错误、旧问题、未读及选中灯光。
- [会话流场景](../../tests/CodexMicro.Desktop.Tests/TaskLightingStreamTests.cs)：运行／等待／空闲快照、两种补丁路径、请求和 flags 的增删、修订缺口、旧 owner、断线、无效消息和释放订阅；冷启动没有 owner 不报错，Micro 连接丢失后重新订阅同一个运行中的 owner。
- [隔离链路场景](../../tests/CodexMicro.Desktop.Tests/TaskLightingEndToEndTests.cs)：真实停止派发及管道读回 → 实时状态订阅 → 临时 rollout 与监控器 → 实际 WPF 键帽。覆盖两页、选中／未选中、结束记录存在／缺失，以及 owner 暂不可用 → 重连 idle → 恢复运行亮蓝。另保留同一个 owner、回合和日志，仅重建 Micro 的监控器、监听器与管道客户端，验证重新订阅恢复蓝灯且没有虚构错误。

隔离链路场景在同一测试进程中使用合成 Codex owner 和离屏 WPF 窗口；按场景重建监控器、监听器或窗口，不启动安装版 Micro 进程。窗口不加载真实应用服务，状态断言读取实际模板画刷。它不证明完整进程启动、实际 Codex 版本兼容、OS 输入、物理设备灯或人工界面验收，也不计为测试分层文档中的 L5 进程旅程。测试目录创建／清理由没有异步接口的目录 API 在后台线程执行，日志读写使用异步 API 或已有后台解析器。

定向运行：

```powershell
dotnet test tests/CodexMicro.Desktop.Tests -c Release --filter "Scope=TaskLighting"
```

全量回归沿用 `scripts/test.ps1`。运行报告保存在忽略的 `.artifacts/`，不把本机会话或原始运行证据作为公开夹具。
