# 验证边界

2026-10-04。用户说明 Windows 正在重新规划测试：单元、组件、内部 E2E、与 Codex 联调并验证业务结果；各部分正交，且与开发过程正交。本文只记录移植约束，具体目录、框架、运行器、夹具和验收场景等待 Windows 更新同步。

| 边界 | 要回答的问题 | 不能代替的验证 |
| --- | --- | --- |
| 单元 | 状态投影、输入规则、尺寸计算等局部规则是否正确 | 完整组件与应用行为 |
| 组件 | 控件或适配器通过其合同与受控依赖协作是否正确 | 对整个应用闭环的验收 |
| 内部 E2E | 自己的应用从入口、交互、路由到反馈是否闭环；对端可控 | 真实 Codex 的协议、焦点和版本兼容性 |
| Codex 联调与业务验收 | 在真实 Codex 中，用户操作是否作用于预期对象并得到预期业务结果 | 不能只以请求发送、IPC 回执或页面打开为成功标准 |

“业务结果”不是再复制一套单元断言。相同场景可以在不同边界使用，但各层承担的证据不同。例如修改新对话模型：规则层验证意图和状态转移；组件层验证目标及适配合同；内部 E2E 验证应用操作链；Codex 联调确认实际新对话及后续回合采用了指定设置。此例说明职责，不声明新对话逻辑已完成移植。

与开发正交：测试有独立入口、准备/清理和结果记录，不要求按实现顺序执行；应用启动、编译、打包不隐式触发真实 Codex 操作。不能为了测试通过改变生产功能含义或加入假成功分支。Mac 也不另立一套与 Windows 冲突的测试层级。

本轮执行构建、资源/元数据静态检查、包签名校验，以及无窗口 MCP 协议与本机绑定只读检查。这些是构建证据，不计作上述任何层级的业务验收。没有新增测试代码，没有启动 GUI 或执行真实会话写入。现有仓库 AGENTS.md 的测试执行约束仍适用。
