# Codex Micro Monitor 1.0.5

Release candidate; not yet published. Desktop and plugin version: `1.0.5`; Windows file/Store version: `1.0.5.0`.

## Changes

- Give each monitored conversation its own IPC connection and receive task, so a large snapshot or a broken subscription cannot close the other conversations' connections.
- Extract lighting metadata while reading snapshots and patches. History text, tool output and attachments are skipped without loading the complete snapshot; unrelated patches still advance the stream revision.
- Keep receiving a snapshot while that connection makes progress, without blocking roster refreshes. Preserve unavailable, owner-change and revision-gap handling for the affected conversation.
- Pin the shared `CodexControl` and `CodexControl.Windows` packages to `1.0.3`.

## Distribution

The candidate includes desktop and plugin ZIPs, a compact Windows x64 ZIP, a source archive and SHA-256 checksums. Desktop ZIPs require .NET 10 Desktop Runtime x64. The bundled plugin manifest uses `1.0.5`; this preparation does not submit the plugin directory listing or a Microsoft Store package.

Snapshot acceptance no longer depends on increasing a full-document byte limit. Retained metadata remains bounded, and invalid or excessive metadata makes only its conversation unavailable. Existing automated checks do not cover every projection boundary or substitute for live installation acceptance.

## 简体中文

本版本为待发布候选版本，尚未公开发布。桌面应用与插件版本为 `1.0.5`，Windows 文件和商店版本为 `1.0.5.0`。

## 变更

- 每条受监控会话使用独立的 IPC 连接和接收任务，大快照或订阅故障不会关闭其他会话的连接。
- 读取快照和补丁时直接提取灯光元数据，历史正文、工具输出及附件不再整份加载；忽略无关补丁时仍推进状态版本。
- 只要所属连接仍有接收进展，就继续读取快照，并允许任务列表继续刷新。不可用、owner 切换和状态版本缺口仍在对应会话内处理。
- 共享组件 `CodexControl` 与 `CodexControl.Windows` 固定为 `1.0.3`。

## 分发

候选包包含桌面 ZIP、插件 ZIP、Windows x64 精简 ZIP、源码包及 SHA-256 校验值。桌面 ZIP 需要 .NET 10 Desktop Runtime x64。捆绑插件 manifest 为 `1.0.5`；本次准备不提交插件目录或 Microsoft Store 包。

快照接收不再依赖提高完整文档的字节上限。保留的元数据仍有资源保护，元数据无效或过量只影响所属会话。现有自动化未覆盖全部投影边界，也不替代真实安装验收。
